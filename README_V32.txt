v34: 스캐너건 - 실제 AR 화면에 1인칭 뷰모델로 배치
====================================================

[발견한 배경]
   코드에 이미 setToolMode(mode,label) 호출이 8곳에 남아있었고, 정의부에는
   "v30: scanner gun removed; compatibility no-op"라는 주석만 있었습니다.
   즉 예전에 스캐너건 UI가 있다가 제거되고 빈 함수만 남아있던 상태였습니다.

[이번 작업]
   - ar.html의 target-reticle 옆에 scanner-viewmodel 요소 추가:
     화면 우하단에 1인칭 시점처럼 스캐너건이 살짝 걸쳐 보이도록 배치,
     은은하게 위아래로 떠다니는 애니메이션 적용
   - setToolMode()를 실제로 되살려서, 기존 8곳의 호출(scan/track/capture/
     analyze 상태 전환)에 맞춰 스캐너건 글로우 색상과 하단 라벨이 자동으로
     바뀌도록 연결:
       · SCAN(신호 탐색) = 시안 블루
       · TRACK(방향 추적) = 골드
       · CAPTURE(포획 중) = 핑크 + 빠른 펄스
       · ANALYZE(제도 분석 완료) = 바이올렛
     → 첨부 이미지 속 스캐너 화면의 SCAN/TRACK/CAPTURE/ANALYZE 색상 코드와
       동일하게 맞췄습니다.
   - 뷰모델은 pointer-events:none으로 터치 조작을 가리지 않음
   - sw.js 캐시 버전 v34로 상향

v36: 위치 신호 획득 개선 + 거리 콤마 포맷 통일 + 문구 줄바꿈 수정
====================================================

[1) 위치 신호를 잘 못 잡는 문제]
   - 8초 이상 못 잡으면 재시도할 때 GEO_FINE(고정확도)만 반복하던 것을,
     이제 FAST/FINE을 번갈아 시도하도록 변경 → 실내처럼 고정확도가 안
     나오는 환경에서도 "정확도는 낮아도 일단 하나라도 잡는" 쪽으로 수렴
   - 못 잡는 상태가 길어지면 안내 문구를 단계적으로 구체화:
     8초~ "신호 탐색 중" → 약 20초~ "신호를 계속 찾고 있어요·창가나
     실외로 이동하면 더 빨리 잡혀요" → 약 30초~ "실내에서는 위치 수신이
     어려울 수 있어요" + 수동 "위치 다시 시도" 버튼 노출
   - 자동으로 위치가 잡히면 재시도 버튼은 즉시 사라짐
   - 참고: 실내(특히 커튼이 쳐진 방 등 창밖 신호가 가려진 공간)에서는
     GPS 특성상 완전한 해결은 어렵습니다. 이번 개선은 "더 빨리, 더 잘
     시도하고, 막혔을 때 사용자가 뭘 해야 하는지 알려주는" 것이 핵심입니다.

[2) 남은 거리 숫자 콤마 표기]
   updateRangeExperience()와 스캐너 라벨(신호 Nm)에서 콤마 없이 표시되던
   부분을 fmtNum()으로 통일해, 1,234m처럼 천 단위 콤마가 항상 붙도록 수정.

[3) 하단 안내 문구 줄바꿈]
   .status-banner에 white-space:pre-line 적용, "카메라 준비 완료 · 위치
   신호를" 다음에서 줄바꿈되도록 텍스트에 개행 삽입. onPosError의
   안내문에도 동일하게 적용.
