JOPAMS GO v17 — 전문가 평가 1~2순위 반영

[1순위 — 신뢰성·정합성]
① 가짜 랭킹 데이터 제거
   - localLeaderboard(): 하드코딩된 가상 인물(윤수호 등) 삭제, 내 기록만 정직하게 표시
   - organizationLeaderboard(): 5개 본부 가짜 기준점수 삭제, 내 본부 실제 점수만 표시
   - motivationRanks(): 점수 역산 기반 가짜 순위 추정 삭제 (서버 연동 전엔 "-" 표시)
   - 서버 연동 시(organizationLeaderboardServer 신규) 실제 제출 데이터로 본부별 합산 표시
   - ranking.html / battle.html: 빈 상태 안내 문구 추가

② XP 계산 로직 단일화
   - totalXP()가 더 이상 max(수집개수*100, profile.xp)로 값을 가리지 않음
   - profile.xp 단일 소스로 통일, 레거시 데이터는 reconcileLegacyXP()가 1회성으로 보정

③ AR 루프 성능 최적화
   - assets/state.js: 저장 데이터를 메모리에 캐싱 (매 호출마다 전체 JSON.parse 하던 것 제거)
   - ar.html: requestAnimationFrame(최대 60fps) → setInterval(120ms, 약 8fps)로 전환
   - 시각적 부드러움은 기존 CSS transition이 담당하므로 체감 품질 저하 없음

[2순위 — 콘텐츠·신뢰 설계]
④ 완주 후 엔드게임 루프 추가
   - 12/12 달성 후에도 AR 탐험 지속 가능 ("재방문 모드")
   - 이미 수집한 체크포인트도 다시 찾아가 미니게임 진행 가능
   - 재방문 성공 시 +15 XP 소량 보상 + minigame_success 이벤트 기록
   - 주간 퀘스트("이번 주 5회 탐험")·캐릭터 성장이 완주 후에도 계속 의미를 가짐

⑤ 확률형 보상(랜덤 상자) 확률 공개
   - assets/liveops.js: lootOdds() 추가, 가중치를 실제 %로 환산
   - expedition.html: 보급상자 패널에 확률 목록 표시

⑥ 랭킹 서버 API 최소 검증
   - server/worker.js: 동일 (name,org) 3초 미만 재제출 차단(429)

⑦ GPS 위치 위조(스푸핑) 기초 방어
   - ar.html: 연속 위치 샘플 간 이동속도가 시속 60km 초과 시 "순간이동"으로 간주
   - 8초간 포획 잠금 + 안내 토스트 표시 (완전한 방어는 아닌 최소 억제 장치)

미반영(3순위, 이번 요청 범위 밖):
   - 정보구조(홈/원정본부/시즌패스 중복) 단순화
   - 미니게임 최초 진입 튜토리얼
   - 기기 변경 시 데이터 백업/이전 수단

후속 업데이트 v19: 서비스워커 캐시 고착 문제 근본 수정
====================================================

[증상]
   - 시크릿 모드(서비스워커 미적용)로는 정상 접속되지만, 일반 모드에서는
     checkpoints.html 등 특정 페이지가 "사이트에 연결할 수 없음"으로 표시됨

[근본 원인]
   - 기존 sw.js는 install 시 caches.addAll(ASSETS)로 전체 파일을 한 번에 캐싱했음
   - 배포 도중 파일 하나라도 일시적으로 404가 나면 addAll() 전체가 reject되어
     서비스워커 설치(install) 자체가 실패
   - 이 경우 브라우저는 새 서비스워커를 폐기하고 "이전에 설치되어 있던 구버전"
     서비스워커·캐시를 계속 사용함 → 그 뒤로 아무리 재배포해도 영구히 고착
   - Cloudflare Pages 기본 리다이렉트(/checkpoints.html → /checkpoints)와 맞물려
     구버전 캐시가 예전 경로 체계에 반응하지 못하면서 접속 불가로 나타난 것으로 추정

[수정 내용]
   - 설치 시 파일을 개별적으로 fetch+caching하고 Promise.allSettled로 처리해
     일부 파일이 실패해도 설치 자체는 항상 성공하도록 변경 (재발 방지)
   - HTML 문서 요청은 "네트워크 우선(network-first)"으로 전환:
     항상 최신 버전을 먼저 시도하고, 오프라인일 때만 캐시로 폴백
   - 이미지·CSS·JS 등 정적 자산은 기존처럼 캐시 우선 + 백그라운드 갱신 유지 (로딩 속도 유지)
   - 외부 오리진(카카오맵 SDK 등) 요청은 서비스워커가 아예 관여하지 않도록 제외 처리
   - CACHE 버전을 v19로 올려 기존 사용자도 다음 접속 시 새 서비스워커로 자동 전환

[현재 고착된 사용자를 위한 안내]
   - 위 수정으로 다음 접속 시 자동으로 정상화되는 경우가 많지만, 안 될 경우
     브라우저 설정 → 사이트 데이터/저장공간에서 jofams.pages.dev 캐시를 한 번
     수동으로 지우고 재접속하면 확실합니다.

후속 업데이트 v20: 카카오맵 재시도 로직 + 겹침 재점검
====================================================

[카카오맵 연결 실패 - 개선]
   - 콘솔에서 JavaScript 키/도메인이 정확히 일치함을 확인 (원인은 전파 지연 또는
     일시적 네트워크 오류로 추정)
   - SDK 로딩 실패 시 2.5초 간격으로 최대 2회 자동 재시도 추가
   - 그래도 실패하면 오류 카드에 "다시 시도" 버튼을 노출해 수동 재시도 가능
   - kakao.maps.load 콜백 내부에서 예외가 발생해도 Promise가 영영 응답하지
     않던 잠재적 문제를 finish() 가드로 방지 (settled 플래그로 중복/무응답 차단)
   - 8초 타임아웃 추가로 무한 대기 방지
   - 브라우저 콘솔에 상세 오류를 남기도록 개선 (개발자 진단 용이)

[텍스트 겹침("collection") 재점검]
   - 이번에도 전체 코드에서 "collection"이라는 영문 텍스트를 렌더링하는 소스를
     찾지 못했습니다. 정적 다중 페이지 구조상 페이지 간 DOM 공유가 불가능하고,
     manifest.webmanifest·CSS 어디에도 해당 문자열이 없습니다.
   - Samsung Internet 등 일부 브라우저는 "컬렉션에 저장" 기능을 영문으로
     "Collection"이라는 라벨로 표시하는 네이티브 UI가 있어, 특정 제스처(길게 누르기 등)
     시 페이지 위에 겹쳐 보일 수 있습니다. 이는 브라우저 자체 UI로 앱 코드로는
     제어할 수 없는 영역입니다.
   - 혹시 몰라 body 레벨에 overscroll-behavior-y:contain을 추가해 브라우저
     제스처 UI가 콘텐츠와 겹칠 여지를 한 번 더 줄였습니다.
   - 확인 요청: 이 글자가 겹쳐 보일 때 "AR 탐험 시작" 버튼을 실제로 눌러서 정상
     작동하는지 확인 부탁드립니다. 버튼이 눌린다면 순수 시각적 현상(브라우저 UI)이고,
     안 눌린다면 실제 앱 버그이니 그 경우 바로 알려주세요.

   /health 응답의 version을 "v34-llama4"로 갱신해 배포 확인이 쉽도록 함.

[배포]
   cd server && npx wrangler deploy
   배포 후 /health에서 "version":"v34-llama4" 확인 → 채팅·퀴즈 재테스트

[교훈]
   Cloudflare Workers AI는 모델이 예고 없이 자주 지원 종료되는 편이라,
   실사용 중 응답이 갑자기 안 되면 먼저 /health 진단 → 채팅 화면의
   [진단] 메시지 확인 → 모델 지원 종료 여부를 의심해보는 순서로 점검하면
   빠르게 원인을 좁힐 수 있습니다.
