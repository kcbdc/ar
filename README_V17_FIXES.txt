JOPAMS GO v17 — 전문가 평가 1~2순위 반영

[1순위 — 신뢰성·정합성]
① 가짜 랭킹 데이터 제거
   - localLeaderboard(): 하드코딩된 가상 인물(윤수호 등) 삭제, 내 기록만 정직하게 표시
   - organizationLeaderboard(): 5개 본부 가짜 기준점수 삭제, 내 본부 실제 점수만 표시
   - motivationRanks(): 점수 역산 기반 가짜 순위 추정 삭제 (서버 연동 전엔 "-" 표시)
   - 서버 연동 시(organizationLeaderboardServer 신규) 실제 제출 데이터로 본부별 합산 표시
   - ranking.html / battle.html: 빈 상태 안내 문구 추가

② XP 계산 로직 단일화
   - totalXP()가 더 이상 max(수집개수*100, profile.xp)로 값을 가리지 않음
   - profile.xp 단일 소스로 통일, 레거시 데이터는 reconcileLegacyXP()가 1회성으로 보정

③ AR 루프 성능 최적화
   - assets/state.js: 저장 데이터를 메모리에 캐싱 (매 호출마다 전체 JSON.parse 하던 것 제거)
   - ar.html: requestAnimationFrame(최대 60fps) → setInterval(120ms, 약 8fps)로 전환
   - 시각적 부드러움은 기존 CSS transition이 담당하므로 체감 품질 저하 없음

[2순위 — 콘텐츠·신뢰 설계]
④ 완주 후 엔드게임 루프 추가
   - 12/12 달성 후에도 AR 탐험 지속 가능 ("재방문 모드")
   - 이미 수집한 체크포인트도 다시 찾아가 미니게임 진행 가능
   - 재방문 성공 시 +15 XP 소량 보상 + minigame_success 이벤트 기록
   - 주간 퀘스트("이번 주 5회 탐험")·캐릭터 성장이 완주 후에도 계속 의미를 가짐

⑤ 확률형 보상(랜덤 상자) 확률 공개
   - assets/liveops.js: lootOdds() 추가, 가중치를 실제 %로 환산
   - expedition.html: 보급상자 패널에 확률 목록 표시

⑥ 랭킹 서버 API 최소 검증
   - server/worker.js: 동일 (name,org) 3초 미만 재제출 차단(429)
   - 1회 최대 점수 증가폭 1,500점 제한, 신규 진입자 최초 제출 상한 6,000점
   - 완벽한 인증 대체는 아니며, 실물 보상이 걸린다면 별도 인증 체계 권장

⑦ GPS 위치 위조(스푸핑) 기초 방어
   - ar.html: 연속 위치 샘플 간 이동속도가 시속 60km 초과 시 "순간이동"으로 간주
   - 8초간 포획 잠금 + 안내 토스트 표시 (완전한 방어는 아닌 최소 억제 장치)

미반영(3순위, 이번 요청 범위 밖):
   - 정보구조(홈/원정본부/시즌패스 중복) 단순화
   - 미니게임 최초 진입 튜토리얼
   - 기기 변경 시 데이터 백업/이전 수단
   - CSS 기술부채(145KB, 중복 미디어쿼리) 정리

====================================================
후속 업데이트: 3순위 반영 + 최종 버그확인/성능 최적화
====================================================

[3순위 반영]
⑧ 정보구조(IA) 중복 정리
   - index.html의 "이번 주 원정" 카드가 expedition.html 주간 퀘스트 탭과
     완전히 동일한 목록을 중복 표시하던 것을 제거
   - 홈에는 "주간 퀘스트 N/3 진행 중" 한 줄 요약 + 원정본부 링크만 남김
   - (일일 미션 카드는 "오늘 할 일" 용도로 성격이 달라 유지)

⑨ 미니게임 최초 진입 튜토리얼
   - 캐릭터별 미니게임(순식=타이밍탭 / 다임=홀드차지 / 훈민=OX퀴즈)을
     처음 만났을 때 규칙 설명 화면을 한 번 보여준 뒤 시작하도록 함
   - 설정(getV4().miniTutorialSeen)에 저장되어 종류별로 한 번만 노출
   - 프로필의 "첫 실행 가이드 다시 보기"를 누르면 미니게임 튜토리얼도 함께 리셋

⑩ 데이터 백업/복원 (기기 변경 대비)
   - state.js: exportJSON()/importJSON() 추가 — 전체 저장 데이터(진행상황,
     프로필, 시즌, 코인, 캐릭터 성장 등)를 JSON 파일로 내보내기/가져오기
   - profile.html: "내 데이터 백업" 섹션 추가 (내보내기/가져오기 버튼)

[CSS 기술부채 — 가벼운 정리]
   - 완전히 동일한 조건의 @media(max-width:390px) 블록 7개 →1개,
     @media(max-width:360px) 블록 3개 →1개로 병합 (내용 손실 없음, 브레이스 균형 검증 완료)
   - 다만 145KB의 대부분은 실제 서로 다른 규칙이라 이번 병합으로는 큰 용량
     절감은 아님 (약 200B) — 본격적인 리팩토링은 더 큰 작업으로 별도 필요

[최종 버그 확인에서 발견/수정한 항목]
   - GPS 스푸핑 감지가 미니게임 진행용 collectingLock 변수를 직접 건드려
     타이밍에 따라 정상 포획 잠금과 충돌할 수 있던 버그 → 별도 spoofLockUntil
     타임스탬프로 분리
   - "연속 탐험" streak 필드가 화면에 표시만 되고 실제로 증가하는 로직이
     어디에도 없어 항상 "1일"로 고정되던 죽은 기능 버그 → syncDaily()에
     날짜 비교 기반 증가/리셋 로직 추가
   - 서비스워커 캐시 버전(sw.js CACHE 상수)이 v16에 고정되어 있어, 코드를
     아무리 수정해도 이미 설치된 사용자에게는 캐시된 구버전이 계속 제공되던
     배포 버그 → v17로 버전업하여 업데이트가 실제로 반영되도록 수정

[성능 최적화 재확인]
   - 이전 라운드에서 적용한 state.js 메모리 캐싱 + AR 루프 120ms 스로틀링이
     이번 3순위 기능 추가(백업, 튜토리얼, IA 정리) 이후에도 동일하게 유지됨을
     코드 검토로 재확인
   - 신규 추가 기능(백업 export/import, 미니게임 튜토리얼, 확률 표시)은 모두
     AR 렌더 루프 밖에서만 동작하도록 설계해 프레임 성능에 영향 없음

[검증 방법]
   - 전체 .js 파일 및 모든 .html 파일의 인라인 스크립트에 대해 node -c 문법 검사 통과
   - getElementById() 참조와 실제 id 속성 간 불일치 여부 전수 대조 완료
   - 모든 페이지의 script 로드 순서(state→ui→app→liveops) 일관성 확인
   - CSS 중괄호 균형 검증으로 병합 후 구조적 손상 없음을 확인
